Why RAM Optimized over CPU Optimized? Onekof is a database-backed web application, not a compute-intensive workload. 6. Why Scenario 2 is the Right Choice

The difference between Scenario 1 and Scenario 2 is 19,768 ETB per 6 months (~$26/month) — the cost of Ethio Telecom's managed Daily Backup service. This section explains why that additional 18% is the most important line item in the budget.

6.1 What Our Script Covers vs. What It Doesn’t

On Tier 3 (Vercel), losing the server doesn’t matter — Vercel is stateless, Supabase manages the database, Vercel Blob stores files. Everything rebuilds automatically on deploy. But on Tier 2 (Ethio Telecom ECS), the VM IS the infrastructure. Our backup-db.sh script only protects one layer:

Data at Riskbackup-db.shETZ Daily Backup
PostgreSQL databaseCoveredCovered
.env.production (secrets, API keys, encryption keys)Not coveredCovered
Docker volumes (Redis session state)Not coveredCovered
Caddy TLS certificates & configurationNot coveredCovered
Local file uploads (Tier 2 stores files on disk, not Vercel Blob)Not coveredCovered
OS-level config (ufw firewall rules, cron entries, Docker daemon config)Not coveredCovered

6.3 The Government Credibility Factor

When a ministry’s IT department asks “What is your disaster recovery plan?” — there are two very different answers:

Scenario 1 answer: “We run a custom bash script that backs up the database daily to the same server’s disk.”
Scenario 2 answer: “We employ a dual-layer backup strategy. Layer 1: Ethio Telecom’s managed Daily Backup service performs automated full VM snapshots with 7-day retention — managed and guaranteed by your own national telecom provider. Layer 2: Our application runs independent daily PostgreSQL backups with 7-day rolling retention for granular database recovery. In a disaster, Ethio Telecom restores the full environment in minutes while we can independently verify data integrity at the application level.”

The second answer wins government contracts. It demonstrates:

  • Partnership with a trusted national provider — Ethio Telecom is a known, auditable entity to government procurement offices
  • Professional-grade disaster recovery — not a startup relying on scripts, but a vendor with managed infrastructure
  • Defense in depth — two independent backup layers is an enterprise standard, not a shortcut
  • Accountability — Ethio Telecom’s SLA backs the VM-level recovery; DAPS Analytics backs the application-level recovery

7. Staging on Vercel: Data Sovereignty Impact

Does staging on Vercel violate data sovereignty? No. Data sovereignty applies to production data — real government users, projects, documents. Staging contains only synthetic test data created by DAPS developers. Production (onekof.et) and staging (onekof.com) are completely separate databases with zero data flow between them.
ConcernAnalysis
Real government data on Vercel?No. Staging uses only synthetic/demo data. Real tenants are on Ethio Telecom only.
INSA certification scopeCertifies app code and security posture, not the hosting location of a test environment.
Separation guaranteeSeparate databases, separate servers, separate credentials. Zero data flow between them.
Industry standardAWS GovCloud, Azure Government all use non-sovereign staging. Sovereignty applies to production data.
If a government client asks"Your production data is hosted exclusively on Ethio Telecom infrastructure in Addis Ababa. Our development testing environment is separate and contains no real data."

When to move staging to Ethiopia: Only if a government contract explicitly requires it, or when revenue justifies the ~60,000 ETB / 6 months additional cost.
